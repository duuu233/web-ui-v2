# IoT 只读监控

> 文档类型：模块与接口契约
> 状态：Active
> 最后核验：2026-10-27
> 事实来源：产品提供的《管理后台需求文档》v1.0、四个线上只读接口、当前源码与自动化回归

## 页面与范围

本模块接入现有后台登录和外壳，通过“IoT监控”菜单进入，独立于产品设备登记模块。只查询，不提供投屏、刷新设备、休眠、OTA等远程控制；页面“刷新”仅读取最新数据。

| 页面 | 路由名 / 路径 | 行为 |
| --- | --- | --- |
| 概览 | iotDashboard / /iot/dashboard | 五项统计；在线率保留1位小数；默认每60秒刷新，可关闭；手动刷新；卡片带在线/告警近24h条件跳转 |
| 设备列表 | iotDevices / /iot/devices | 设备号模糊查询、在线/离线、20/50/100分页；设备行进入详情，日志入口预填设备号 |
| 设备详情 | iotDeviceDetail / /iot/devices/:deviceNo | 设备表/实时在线分别显示，差异提示；完整影子分组、未知字段保留、最近20条日志；返回列表、全部日志 |
| 日志 | iotLogs / /iot/logs | 精确设备号、五分类、结果、起止时间；分页；全文展开、msgid复制、设备详情跳转 |

列表条件修改后点击“查询”才生效，查询回第1页，切页保持已经应用的条件；重置清空全部条件。普通首次进入日志页默认近24小时，用户可清空；由设备进入则自动按该设备查询，由概览告警进入则使用ALARM及近24小时。

设备号展示加冒号、接口传大写12位无冒号。设备查询支持部分关键词，日志与详情要求完整十六进制设备号。分页使用page/size，默认20，size选项20/50/100。离线值false、统计/电量/容量的0均保留；缺失值展示“—”。时间按Asia/Shanghai展示；服务端无时区时间串按上海墙上时间保留，ISO/时间戳按上海时区格式化，起止时间按包含边界查询并校验格式、日期及先后顺序。

## 接口与鉴权

独立GET客户端位于src/api/iotAdminClient.js，只允许以下四条路径；不使用现有ZoneAdmin请求实例，不发送userToken、randomString、sign或Cookie。

| 方法 | 路径 | 查询参数 |
| --- | --- | --- |
| GET | /admin/stats | 无 |
| GET | /admin/device/list | page、size；可选keyword、online |
| GET | /admin/device/detail | deviceNo |
| GET | /admin/log/list | page、size；可选deviceNo、category、result、startTime、endTime |

响应为{code:0,msg,data}；分页为data.total/page/size/list。独立15秒超时，离开页面或后续查询会中止旧请求，迟到成功/错误不覆盖当前页面；概览定时器和页面时钟在离开/销毁后清理。加载和失败保留已显示的数据与列表总数，避免分页因暂时总数0退回第一页；切换真实/演示数据源会先清空旧来源的数据，防止混淆。

401提示联系管理员配置Token，4000显示参数错误，4044明确设备不存在并可返回列表，5000提示服务异常；均显示接口code/msg和重试。错误与日志文本按普通文本渲染，不执行HTML。

## 数据展示与演示

在线绿、离线灰；电量<20红、20–40橙、>40绿；WiFi信号>=-60绿、-75到-60橙、<-75红。TF present/absent分别已插卡/无卡；SUCCESS绿，FAILED/TIMEOUT红，DOWNLOADING/FLASHING蓝。数值缺失不会误判为0。

影子按电源/连接、存储/显示、版本/心跳分组；未知字段进入“其他字段”，对象以JSON文本展示，tfTotal/tfUsed标明MB。空影子有独立提示。日志固定以服务端分页为准；详情最近日志前端倒序并限20条，不全量拉取日志，不提供未有接口的趋势图或导出。

默认连接真实接口，页头可显式开启“演示数据”；合成数据包含在线/离线、分页、空影子、状态差异和未知字段。演示场景支持正常、空、5000、401、4000及详情4044；来源始终显式标明，不能将演示数据视作线上结果。

## 环境与上线

- VITE_IOT_ADMIN_BASE_URL：可选，默认https://iot.boltfox.cn。可配置为同源反向代理前缀（如/iot-api）。
- VITE_IOT_ADMIN_ENV：可选，默认“生产”，可设置为“测试”等环境标识。
- VITE_IOT_ADMIN_MODE：仅mock时默认演示，其他值默认真实。
- 可在应用启动前由运行环境注入window.__IOT_ADMIN_CONFIG__，字段baseURL可覆盖地址，internalToken可按内部部署需要注入X-Internal-Token。不要把真实值写进源码、文档、VITE构建变量或持久化浏览器存储；更推荐同源代理由服务端添加该Header。

2026-10-27线上读接口无需内部Header即可返回数据；这不代表已完成上线安全配置。发布前由服务端运维启用xt.admin.internal-token、收紧CORS并配置内网/IP限制，前端对应配置同源代理或运行时Header。本次没有服务器配置或部署操作。
